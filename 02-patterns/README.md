# Patterns

Patterns are reusable architecture and delivery shapes.

Each pattern is written as:

- **Context** — when it applies
- **Problem** — what risk or ambiguity must be addressed
- **Decision** — what is chosen
- **Trade-offs** — what you gain / lose
- **Operating notes** — what support needs
- **Evidence expectations** — what artefacts should exist
- **Anti-patterns** — what should be avoided
- **Acceptance criteria** — what must be true before handover or publication
